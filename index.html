Who I am

About Me

I am passionate about doing things well and doing them with purpose — whether designing a test case, leading an audit, or guiding a meditation at the start of a training session.

I began my career as an Industrial Engineer at multinational companies like Tupperware, DuPont and Procter & Gamble, where quality, regulatory compliance, and continuous improvement were at the core of my work.

Later, at TSYS, reporting directly to the CTO, I became a key bridge between business areas and the Software Development team. Over time I discovered that behind every Non-Conformity, every audit, and every improved process, there was something I was deeply passionate about: finding errors before they reach the end user.

Today I am training as a QA Engineer at the TripleTen Latam Bootcamp, working on real projects applying manual testing, test case design, API testing with Postman, and defect management in JIRA. What sets me apart is more than a decade of real experience in quality, processes, and communication with technical teams.

Project 02
🛒 Urban Grocers
REST API Testing · TripleTen Bootcamp, Sprint 4 (2026)
API Testing
🎯 Problem

Validate that the REST API for kit management and grocery delivery correctly handled requests — including happy-path scenarios, boundary conditions, missing fields, invalid data types, and error handling.

📊 Results & Impact
71

37

⚙️ What I Did

Designed and executed 71 test cases using Postman against three API endpoints:

  • POST /api/v1/kits — kit creation, validating the name field with boundary values and invalid types
  • POST /api/v1/kits/:id/products — adding products to a kit, validating unique product limits and duplicate IDs
  • POST /order-and-go/v1/delivery — delivery feasibility, validating deliveryTime, productsCount and productsWeight
✅ Learning

Discovered that the API accepted invalid requests (null fields, negative values, wrong data types) returning 200 OK instead of the expected 400 Bad Request errors. This experience reinforced the importance of testing not only happy paths but all boundary and negative scenarios in API validation.
